# 운동 일지 — 설치 및 배포 가이드

개인 웨이트 트레이닝 기록을 모바일에서 입력하고, 모바일/태블릿/PC 어디서든 실시간으로 확인할 수 있는 PWA(설치형 웹앱)임. Firebase(Google 로그인 + Firestore)로 기기간 데이터가 자동 동기화됨.

## 포함된 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 본체 (대시보드/기록입력/이력) |
| `firebase-config.js` | Firebase 프로젝트 접속 정보 (직접 입력 필요) |
| `manifest.json` | PWA 설치 설정 |
| `sw.js` | 오프라인 캐싱용 서비스 워커 |
| `firestore.rules` | Firestore 보안 규칙 (본인 데이터만 접근 가능) |
| `icons/` | 앱 아이콘 |

---

## 1. Firebase 프로젝트 만들기

1. [console.firebase.google.com](https://console.firebase.google.com) 접속 → Google 계정으로 로그인 (기존 계정 사용 가능)
2. **프로젝트 추가** 클릭 → 프로젝트 이름 입력 (예: `workout-log`) → Google Analytics는 꺼도 무방함
3. 프로젝트가 생성되면 왼쪽 메뉴에서 다음 두 가지를 켤 것:
   - **Authentication** → "시작하기" → 로그인 방법 탭 → **Google** 활성화 → 저장
   - **Firestore Database** → "데이터베이스 만들기" → 위치는 `asia-northeast3(서울)` 권장 → 프로덕션 모드로 시작
4. Firestore 보안 규칙 적용: Firestore Database → **규칙** 탭 → 이 프로젝트에 포함된 `firestore.rules` 파일 내용을 그대로 붙여넣고 **게시**
   (본인 계정 uid로만 자신의 기록에 접근 가능하도록 제한하는 규칙임)

## 2. 웹 앱 등록 → 설정값 복사

1. 프로젝트 개요 화면(⚙ 옆 홈 아이콘) → 하단 **앱 추가** → 웹(`</>`) 아이콘 선택
2. 앱 닉네임 입력 (예: `workout-log-web`) → Firebase Hosting 체크는 선택사항 → 앱 등록
3. 화면에 표시되는 `firebaseConfig = { apiKey: ..., authDomain: ..., ... }` 값을 복사
4. 이 프로젝트의 **`firebase-config.js`** 파일을 열어 `여기에_...` 부분을 방금 복사한 값으로 교체 후 저장

```js
window.FIREBASE_CONFIG = {
  apiKey: "AIza...",
  authDomain: "workout-log-xxxxx.firebaseapp.com",
  projectId: "workout-log-xxxxx",
  storageBucket: "workout-log-xxxxx.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abcdef..."
};
```

설정 전까지는 앱을 열면 "Firebase 설정 필요" 화면이 뜨며 기록 저장/동기화가 동작하지 않음. 설정 완료 후에는 이 화면이 사라짐.

## 3. Authentication 승인된 도메인 등록 (배포 후 1회)

Google 로그인은 등록된 도메인에서만 동작함. Firebase 콘솔 → Authentication → Settings → **승인된 도메인**에 실제 배포할 도메인(예: `workout-log-xxxxx.web.app`, 또는 직접 쓰는 커스텀 도메인)이 포함되어 있는지 확인. Firebase Hosting을 쓰면 자동으로 추가됨.

---

## 4. 배포하기 (Firebase Hosting 권장 — 무료)

로컬 PC에 Node.js가 설치되어 있어야 함.

```bash
npm install -g firebase-tools
firebase login                      # Google 계정 로그인
cd workout-log-app                  # 이 폴더로 이동
firebase init hosting               # 기존 프로젝트 선택, public 디렉터리는 "." (현재 폴더), SPA 재작성 질문은 "아니오"
firebase deploy
```

배포가 끝나면 `https://<프로젝트id>.web.app` 형태의 실제 URL이 발급됨. 이 주소를 모바일 브라우저로 열면 됨.

> 다른 정적 호스팅(Netlify, Vercel, GitHub Pages 등)도 사용 가능함. 폴더 전체를 그대로 업로드하면 됨 — 단, HTTPS가 지원되어야 PWA 설치와 Google 로그인이 정상 동작함.

---

## 5. 모바일에 설치하기 (홈 화면에 추가)

배포된 주소를 모바일 브라우저로 연 뒤:

- **iPhone (Safari)**: 하단 공유 버튼(⬆) → "홈 화면에 추가"
- **Android (Chrome)**: 우측 상단 메뉴(⋮) → "홈 화면에 추가" 또는 자동으로 뜨는 설치 배너 사용
- **PC (Chrome/Edge)**: 주소창 오른쪽의 설치 아이콘(⊕/모니터 아이콘) 클릭 → "설치"

설치하면 일반 앱처럼 아이콘이 생기고, 주소창 없이 전체 화면으로 실행됨.

## 6. 앱 사용법

1. 처음 열면 **PIN 입력 화면**이 뜸 (기본값 `1234`) — 기기 단위의 간단한 잠금이며, 코드 상단 `GATE_PIN` 값을 바꾸면 변경됨
2. PIN 통과 후 **Google 계정으로 로그인** 화면이 뜸 — 실제 데이터 접근 권한은 이 로그인으로 보호됨. 본인 계정으로 1회 로그인하면 이후에는 로그인 상태가 유지됨 (로그아웃은 상단 우측 아이콘)
3. 로그인한 **같은 Google 계정**으로 다른 기기(모바일/PC)에서 열면 동일한 기록이 실시간으로 동기화됨
4. **기록 입력** 탭에서 날짜/부위/운동/중량/세트별 반복수를 입력 후 저장 → Firestore에 즉시 저장되고, 오프라인 상태에서도 임시 저장 후 온라인 복귀 시 자동 반영됨 (Firestore 오프라인 캐시 기능)
5. **대시보드**의 각 차트는 저장된 기록을 바탕으로 실시간 계산됨 (주차 번호는 ISO-8601 기준, 월요일 시작). "최근 기록" 카드는 제목을 눌러 접고 펼칠 수 있음
6. **이력** 화면에서는 기록별 삭제(휴지통 아이콘, 삭제 전 확인창 뜸)가 가능하고, 기록이 많아 내용을 다 못 볼 때는 각 기록의 ⓘ 아이콘을 눌러 세트별 상세를 툴팁으로 확인 가능함
7. 모바일/태블릿에서는 화면을 좌우로 스와이프하면 대시보드 ↔ 기록 입력 ↔ 이력 순서로 탭이 전환됨 (칩 목록 등 가로 스크롤 영역 위에서는 스와이프가 걸리지 않음)

## 7. 과거 Google Sheets 기록 가져오기

기존에 구글 시트에 기록해 두었던 과거 이력(2026-01-01 ~ 09-09, 총 622건, 세트별 반복수까지 포함된 원본 데이터)이 `legacy-data.js` 파일에 미리 변환되어 포함되어 있음. 별도 설정 없이 앱에서 버튼 한 번으로 가져올 수 있음.

1. 앱에서 **Google 로그인**까지 마친 상태로 **이력** 탭으로 이동 → 화면 우측 상단의 아이콘(⤓ 모양) 클릭
2. 뜨는 말풍선(툴팁)에 원본 건수·날짜 범위와 현재 진행 상태가 표시됨
3. **가져오기 시작** 클릭 → 말풍선 안에서 진행률이 올라가고, 완료되면 "가져오기 완료됨 (622 / 622건)"으로 바뀜
4. 대시보드/이력 화면에는 자동으로 즉시 반영됨 (같은 말풍선을 다시 열어 상태 재확인 가능)

**중복 걱정 없이 여러 번 눌러도 됨** — 가져온 각 기록은 고유 ID(`legacy_0001` ~ `legacy_0622`)로 저장되어, 다시 눌러도 새로 추가되지 않고 같은 내용으로 덮어써짐. 이미 입력해 둔 다른 기록(직접 입력한 기록)에는 영향 없음.

**참고할 점**
- 볼륨(v)은 이 앱의 계산식(중량 × 세트별 반복수 합)으로 통일해서 다시 계산함. 원본 시트에서 일부 종목(덤벨/바벨 컬, 래터럴 레이즈 일부)에 걸려 있던 별도 1.5배 가중치는 반영하지 않음 — 전체 기간 수치를 하나의 기준으로 일관되게 비교하기 위함. 필요하면 원본 시트 링크(앱 하단 각주)에서 원래 값을 확인 가능함.
- 다른 Google 계정으로 로그인하면 그 계정 기준으로 별도로 가져와야 함(계정마다 데이터가 분리됨).
- 과거 기록을 다시 가져올 필요가 없다면 이력 화면의 가져오기 아이콘은 그냥 두면 됨 — 다른 화면 동작에는 영향 없음.

## 8. 참고 — 데이터 구조

Firestore 경로: `users/{내 uid}/records/{기록id}`

```json
{
  "date": "2026-09-09",
  "part": "대흉근",
  "ex": "push up",
  "w": 45,
  "reps": [40, 50],
  "v": 4050,
  "createdAt": "(서버 타임스탬프)"
}
```

기존 Google Sheets에 기록된 과거 이력을 이 앱으로 옮기고 싶다면, 위 형식에 맞춰 Firestore 콘솔에서 직접 문서를 추가하거나 별도 가져오기 스크립트 작성을 요청할 것.

## 문제 해결

- **"Firebase 설정 필요" 화면이 계속 뜸** → `firebase-config.js` 값이 정확히 입력되었는지, 오타는 없는지 확인
- **Google 로그인 버튼을 눌러도 반응 없음** → 배포된 도메인이 Firebase Authentication의 "승인된 도메인" 목록에 있는지 확인. `file://`로 직접 열면 로그인이 동작하지 않음(반드시 HTTPS로 배포해서 사용)
- **다른 기기에서 기록이 안 보임** → 같은 Google 계정으로 로그인했는지 확인. 상단 배지가 "동기화됨"으로 바뀌는지 확인
- **PWA 설치 버튼이 안 보임** → HTTPS 배포가 필요함. `file://`나 사설 IP(http)로는 설치 배너가 뜨지 않음
- **새로 배포했는데 화면이 그대로임 / 버튼을 눌러도 반응이 없어 보임** → 모바일에 설치된 PWA는 서비스 워커가 이전 버전 화면을 캐시해 두고 있어서 그럴 수 있음. `sw.js`가 v2로 갱신되면서 앞으로는 새 버전 배포 시 자동으로 한 번 새로고침되지만, 이미 설치된 앱이 v1을 쓰고 있었다면 한 번은 앱을 완전히 종료 후 재실행(또는 재설치)해서 새 버전을 받아야 함
- **firebase-config.js를 실수로 자리표시자로 덮어씀** → 배포 후 계속 "Firebase 설정 필요" 화면만 보인다면 이 경우일 가능성이 높음. 원래 채워뒀던 실제 프로젝트 값(apiKey 등)으로 다시 채워넣고 재배포할 것
